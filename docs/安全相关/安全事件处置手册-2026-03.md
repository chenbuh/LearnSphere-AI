## 阶段 2：清理 Git 历史

### 2.1 完整备份（必须，不可跳过）

```bash
cd "E:/Project/LearnSphere  AI"
# 裸克隆备份，用于出错时回滚
git clone --mirror . ../LearnSphere-AI-backup.git
```

### 2.2 安装 git-filter-repo

```bash
pip install git-filter-repo
git filter-repo --version
```

### 2.3 从全部历史中移除泄露文件

```bash
git filter-repo \
  --path backend/learnsphere_ai_production.sql \
  --path backend/learnsphere_ai_backup_20260306.sql \
  --path dump.rdb \
  --invert-paths \
  --force
```

### 2.4 验证历史已清除

```bash
# 应无任何输出
git log --all --oneline -- backend/learnsphere_ai_production.sql
git log --all --oneline -- backend/learnsphere_ai_backup_20260306.sql
git log --all --oneline -- dump.rdb

# 确认文件在历史任意版本中都不存在
git rev-list --all --objects | grep -E "learnsphere_ai_(production|backup)|dump.rdb"
```

### 2.5 清理引用与回收对象

```bash
git reflog expire --expire=now --all
git gc --prune=now --aggressive
```

### 3.1 远端侧必须人工完成的动作

- Settings → Code security → 检查是否有人已 Fork。**Fork 会保留旧对象**，需联系各 Fork 所有者删除或重提。
- 联系 GitHub Support 请求清理已缓存的对象（若仓库曾公开或已归档）。

- 若仓库曾公开，向平台提交工单请求清理。


## 阶段 5：合规处置

若仓库曾在公开状态可访问，按数据泄露事件处理：

1. **影响范围确认**：从备份中统计受影响用户（邮箱、用户名、订单）。
2. **用户告知**：向受影响用户发送通知，说明泄露数据项与建议措施。
3. **监管报告**：依据《个人信息保护法》第五十七条，发生或可能发生个人信息泄露、篡改、丢失的，应当立即采取补救措施，并通知履行个人信息保护职责的部门和个人。
4. **留档**：记录事件时间线、处置动作、通知记录，形成事件报告。
